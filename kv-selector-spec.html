Near-memory KV-read selector

A content-aware KV-read skipper as a small near-memory coprocessor: keep per-page key summaries in on-chip SRAM, score them against the query, pick the top-k pages, and touch the DRAM arrays only for survivors. Block diagram, timing model, and the area/latency budget — with the honest overheads named.

← StudyResultsCode

1Mechanism

Each KV page (P tokens) is summarized by per-channel min/max of its keys. For a query q, an upper bound on the max attention score any token in a page can produce is crit = relu(q)·Kmax + min(q,0)·Kmin — sign-correct, and computed without reading the page's full keys. Read only the top-k pages by crit (plus the sink page and the query's own page). Because the score is an over-approximating bound, it rarely drops a page that mattered — high recall, tunable by the page budget.

2Block diagram

Decide-on-compute, enforce-on-memory: the compute die sends a tiny query descriptor; the base die scores SRAM-resident page summaries, selects, and gathers only survivor pages from the DRAM arrays. The expensive arrays are touched for survivors only; the summaries (write-time min/max) live in fast on-chip SRAM.

3Timing

Per-page decision is one D-wide MAC (~1 cycle); the full scan is nP page-scores at SRAM speed. It's a serial preamble before the gather, but token t+1's scan overlaps token t's DRAM gather, so the scan hides under the memory stall.

Honest caveats. The summaries cost +1/P of KV traffic and storage — real, and already subtracted from the reported energy savings. The scan is O(nP), so it grows linearly with context; at very long context use a larger page P (fewer pages, coarser selection) or hierarchical selection (coarse super-pages → refine only the promising ones, turning the scan ~logarithmic). Placement matters: keep summaries in SRAM on the base die and score there, so the query goes down once and survivors come up once — scoring on the compute die instead would cost a link round-trip per step. The min/max bound is content-aware but approximate; validate the quality cost empirically (the study measures it against the sink+window floor).

Companion to the study and the code. First-order area/latency; absolute numbers pending a foundry PDK. Instance of the "bit-manipulation / selection tax" thesis: the ops GP processors do poorly (gather, select, format) become tiny fixed-function units at the memory boundary.
