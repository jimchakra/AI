AI Inference Architecture · Real-Time Systems

NACK, don’t hang

A hard-real-time principle from the modem, applied to AI inference: you cannot meet a deadline by over-provisioning against an unbounded worst case — and that worst case lives in the shared control plane, not the arithmetic. Detect the impending miss early and emit a cheap, bounded-loss fallback the system is built to absorb — a NACK — instead of blocking into a cascading stall. Two knobs below are live simulations of exactly this trade.

01The principle — from HARQ to inference

In a modem there is a hard subframe deadline to return feedback to the gNB. Here is the subtlety outsiders miss: the PHY datapath is not the risk — it is provisioned, by construction, to decode the worst tolerated channel within a fixed timeline (worst-case channel estimation, equalization, and FEC are all inside the budget). What is unbounded is the control plane. A modern modem runs L2 (MAC/RLC/PDCP), RRC, and PHY control across a multi-core complex, and those tasks contend for shared compute: a burst of cache misses, an interrupt storm, bus contention, or several tasks colliding on one core can stretch a control task’s execution time with no warning. When such a task will miss its slot, a robust design does not block waiting for it — it emits a bounded-loss fallback (a NACK, costing one HARQ retransmission) that the protocol is built to absorb. The alternative — hanging — times out up the stack into RLC retransmission, then RRC re-establishment, then a dropped call. A small, deterministic loss replaces an unbounded, cascading one. The uncertainty is never in the arithmetic; it originates in the shared compute resource — cache, bus, IRQ, scheduling. That is exactly the shape of the problem in AI inference serving, at two very different time scales.

02Layer 1 — token-deadline anytime KV degradation

A streaming decoder (voice, live translation, an agent in a control loop) owes one token every D ms. The deterministic part of a token’s cost — compute plus the KV read at the current context — is provisionable, exactly like the modem PHY sized for the worst channel. What actually causes misses is the contention tail: co-tenant memory-bandwidth pressure, a kernel-launch or scheduler stall, a straggler rank in a tensor-parallel group. At short context there is slack to absorb those spikes; as context grows the deterministic baseline eats the slack, so the same contention spike begins tipping tokens over D. A rigid decoder rides it out and accumulates lag until the stream freezes. A robust decoder predicts the overrun and trims the KV budget to reclaim slack — emitting a slightly worse token on time. That degraded token is the NACK, and its quality cost is the measured Quest curve (budget → Δppl), not a guess.

Read it like a control-task time budget, not a link budget. Below the wall the two policies are identical — there is enough slack to absorb contention, so no NACKs are needed and quality cost is zero. As context erodes the slack (or contention climbs), the rigid decoder’s on-time rate collapses and lag runs to tens of seconds (a frozen stream). The robust decoder converts that cliff into a gentle slope: it reclaims slack by reading less KV, paying a bounded per-token Δppl and staying on time. The deepest fallback, if even the smallest budget won’t fit (extreme contention), is to emit a hold/duplicate token — a true erasure, the exact analog of DTX/blanking when even a NACK can’t make timing.

03Layer 2 — serving-side admission control vs congestion collapse

Now the deadline is a TTFT SLO and the tail is bursty arrivals. A single server (100 req/s capacity) faces load that spikes above capacity. A rigid server queues everything: under overload, latency explodes, every request misses the SLO, and timed-out clients retry — a storm that drives ~100% utilization doing ~0 useful work (congestion collapse). A robust server runs admission control: if the predicted wait exceeds the SLO, it rejects immediately with 503 + backoff — a NACK — so admitted work meets the SLO and goodput stays high. The rejected request is cheap and recoverable; the hung queue is not.

The retry storm is the point. Turn retry fraction up and watch the rigid curve fall toward zero rather than levelling off: a server that neither finishes work in time nor refuses it converts every client timeout into more load. Shedding breaks that loop — the same reason a modem NACKs early instead of letting a receive buffer back-pressure the whole pipeline. Tightening the SLO lowers the achievable plateau (less slack to absorb variance), which is the honest cost: admission control doesn’t create capacity, it protects the capacity you have.

04The throughput payoff — capacity vs the tail guarantee

First, the honest ordering, because it is easy to misread this as advocating a shaky system with a panic button. It is the opposite. The way you make a tight deadline safe is mixed-criticality partitioning: tight-deadline tasks get guaranteed resources — many tiny cores with SRAM scratchpad, no cache, no contention, so their worst-case execution time is deterministic by construction — while large throughput jobs run on powerful shared cores where timing uncertainty is accepted. Graceful degradation is the backstop for the residual tail that partitioning cannot kill (tail events still happen). And that backstop pays for itself in throughput.

The argument in one move: fix a latency-percentile guarantee and ask how much load a single server can carry while meeting it. Tighten the percentile and sustainable load collapses — you are spending capacity as insurance against a heavy contention tail. Keep the same percentile but truncate the tail with an anytime degrade (read KV until the deadline, then stop), and the tail cost migrates from missed deadlines to bounded quality loss — so you can run far hotter for the same guarantee.

The infeasibility point is the real headline. A gentle decline from P99 to P99.5 is just an insurance tax. But past roughly P99.8 the hard policy does not merely get expensive — it becomes impossible at any load, because a single contention spike makes one request’s service alone exceed the deadline, and no amount of idle headroom fixes a tail that crosses D. Truncation is the only thing that can. So an ultra-tight SLO tier is only offerable if you have an anytime-degrade capability — degradation is not a corner-cutting move, it is what makes the premium product feasible.

Tiered QoS — the business model this unlocks

The reclaimed capacity is sellable as differentiated QoS. Not every request wants the same guarantee: a radiologist reading a scan wants the highest tier — full quality, tightest latency, no degradation, and will pay for it; someone using AI to touch up a photo or for novelty fortune-telling does not, and would rather pay less. So run two classes on the same silicon: premium gets priority and the guaranteed low-contention resources (its tail is engineered out, per the partitioning above), so it holds its SLO at full quality; economy shares the contended pool and degrades first under pressure. Under load the economy tier absorbs the degradation that protects the premium SLO — which is exactly what lets the provider run the fleet hot instead of idling it as insurance.

05Honesty notes & the tighter analog

Where the analogy is exact, and where it strains. A HARQ NACK is bounded: one retransmission and the frame is recovered. Layer 2’s shed request is just as clean — it comes back and succeeds. Layer 1 is the strained one: a degraded token can propagate autoregressively, so its Δppl is a per-token quality proxy, not a hard recovery bound. That’s why the controller should prefer to degrade on low-stakes tokens and stay conservative. The tighter analog that restores the bound is speculative decoding under a deadline: accept the draft token without full verification when time is short, and the verify loop corrects it on a later step — a true detect–fallback–retransmit, one-for-one with HARQ. I built the KV-budget version here because its quality axis is measured on a real model; the speculative variant is the natural follow-on.

Model bounds. Both sims are first-order and illustrative — the shapes (cliff vs plateau) are the claim, not the absolute milliseconds. Layer 1’s compute/KV constants are calibrated so the deterministic baseline consumes its deadline slack near a realistic context, at which point the contention tail (the jitter term) drives the misses — not the deterministic read itself; its quality axis (budget→Δppl) is the real Quest measurement. Layer 2 is a single-server M/G/1-style queue with a mean-preserving 2-state burst process and a retry feedback loop; production serving adds continuous batching, multiple replicas, and priority classes, all of which move the numbers but not the phenomenon. 06Where this sits in the literature

The idea is not new to computing — it is just scattered across three communities that rarely cite each other, and none of them frames the trigger the way a modem engineer does (contention-induced deadline miss) and ties the graceful lever to a near-memory KV datapath. That intersection is the open space.

1 · Real-time systems — the exact formalism

The classical imprecise computation model (Liu et al., late 1980s–90s) splits a task into a mandatory part and optional parts, and sheds the optional parts under deadline pressure — a bounded-accuracy loss instead of a miss. This is precisely the NACK principle. It was carried directly into deep learning by “Scheduling Real-time Deep Learning Services as Imprecise Computations” (arXiv 2011.01112, 2020), which casts a DNN as mandatory + optional stages and reports near-zero deadline violations at a small accuracy cost — the same trade this page simulates. The RT community also has anytime algorithms and deadline-aware DNN scheduling at the edge (EdgeServing; real-time work-conserving GPU scheduling for concurrent inference).

2 · Adaptive-computation ML — the graceful lever

The mechanism for a bounded-loss model output already exists: early-exit networks (BranchyNet, 2016; Shallow-Deep, DeeBERT), anytime multi-scale nets (MSDNet), and for LLMs specifically Confident Adaptive Language Modeling (CALM) (Schuster et al., NeurIPS 2022), which exits early per token with a provable quality bound vs the full model. Speculative decoding (Leviathan et al., ICML 2023) is the verify-and-correct variant — the tightest HARQ analog. But this whole line is motivated by average speedup, almost never by hard-deadline robustness under contention.

3 · ML serving systems — mostly engineer the variability away

The serving community attacks the same tail, but its instinct is to remove variability rather than degrade gracefully. “The Tail at Scale” (Dean & Barroso, CACM 2013) is the canonical statement that tail latency comes from shared-resource contention, background work, and queueing — your control-plane point, for datacenters. Clockwork (OSDI 2020) makes DNN serving predictable by eliminating variability from the bottom up. The current LLM wave — Orca, vLLM/PagedAttention, Sarathi-Serve, DistServe, Llumnix — is SLO-aware scheduling; admission control / load-shedding (this page’s Layer 2) is standard overload practice now reaching LLM serving, and recent work explicitly measures the noisy-neighbor / predictability problem on shared GPU clusters.

The whitespace. Community 1 has the deadline-miss-under-contention framing but treats the model as a black-box accuracy knob. Community 2 has the fine-grained quality lever (early-exit, KV budget) but tunes it for throughput, not deadlines. Community 3 mostly tries to make the tail disappear rather than plan a bounded-loss fallback for when it doesn’t. Almost nobody (I found no direct prior art) does all three at once: partition by criticality so the tight path runs on guaranteed low-contention resources, then absorb the residual contention tail with a near-memory KV read-budget cut whose quality cost is measured, and sell the reclaimed capacity as tiered QoS. That is the modem engineer’s reflex — guaranteed resources first, bounded-loss backstop second, throughput as the payoff — applied to inference silicon, and it is the through-line from this page to the memory-boundary study.
